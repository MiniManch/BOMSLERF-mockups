Build spec

BehaviourRule
OpenTap the character card on the home screen. Panel fades in over a scrim, 0.15s. Home screen stays mounted behind it.
Close✕, tap outside the panel, or Android back. Closing without selecting keeps the previous choice.
Select an unlocked characterSlot gets the gold border, detail pane updates, Select becomes active. Tapping Select saves and closes.
Tap a locked characterToast "Not yet available", 1.5s. Selection unchanged, detail pane unchanged. No modal, no store, no navigation.
Already-selected characterSelect reads "Selected" and is inert, or just closes the panel. Never a second write.
PersistenceSelection survives app restart. Store locally and send to the server — the server is the authority (BOM-130).
PortraitOne container, fixed aspect. Placeholder silhouette until BOM-99 lands, then swap the asset without touching layout.
Ability iconsFour slots, left to right: Passive · Basic · Skill · Ultimate. Placeholder glyphs for now. No tooltips in this ticket.
Stats come from the server, never from the client

Read every number from the characters endpoint (BOM-39). Do not hardcode 2,240 or 165 in the panel — those values live in the character DB and Steve is still able to change them. The figures shown above are the current correct ones; Jira had them wrong until yesterday.

No team colour anywhere in this panel

Tank Category Spec golden rule: a character keeps its own colours regardless of side. There is no blue or red version of Aldric. The only ally/enemy signal in the whole game is the HP bar above the character in-match — green for ally, red for enemy. This panel has no team context at all, so it shows the character exactly as it is.

Scope boundary — read this before building

There is a real overlap between this ticket and BOM-121 (Sprint 4), which builds a full character select screen with two characters, stat comparison and ability previews.

With one unlocked character, a selection does not exist in any meaningful sense. So the recommendation is:

  • Build now: the card and its two states on the home screen, the panel shell, the roster list with locks, the detail pane, and persistence.
  • Leave for BOM-121: stat comparison between characters, ability tooltips or descriptions, portrait animation, filtering or roles, anything to do with a second playable character.

Built this way, BOM-121 extends the panel rather than replacing it, and none of this work gets thrown away.
